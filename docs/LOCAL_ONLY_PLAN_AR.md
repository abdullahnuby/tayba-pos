# خطة التحويل إلى طيبة POS محليًا فقط

## الهدف
تشغيل البرنامج على جهاز المحل مع SQLite محلية كمصدر البيانات الوحيد. لا Google Sheets ولا Apps Script ولا Cloudflare D1/KV في مسار التشغيل.

## ما نُفذ في فرع local-only-hardening
- حماية مسارات قراءة المشتريات والتحصيلات والمدفوعات وسجل التدقيق والإعدادات حسب الجلسة والدور.
- تحويل Prisma إلى SQLite/Node، وتحديد ملف البيانات الافتراضي `data/tayba.db`.
- إنشاء طبقة معاملات محلية للبيع والشراء ومرتجعاتهما وإلغاء واستئناف الفاتورة وتعديلات المخزون.
- جعل الجرد متعدد الأصناف عملية ذرية واحدة؛ لا تبقى تغييرات جزئية عند فشل أحد البنود.
- التحقق من الكمية المرتجعة على بنود الفاتورة الأصلية واستخدام الأسعار/التكاليف المحفوظة، وربط المرتجعات بمنفذها.
- تحديث تحصيل العملاء وسداد الموردين والأرصدة في معاملة واحدة.
- تعديل تقارير الربح لتراعي المرتجعات الجزئية ومرتجعات الشراء.
- تعديل إغلاق الوردية لاستخدام المقبوضات الفعلية ورد النقد فقط، ومنع إغلاق الوردية مرتين.
- استبدال شاشة المزامنة بنسخ احتياطي SQLite وتصدير، وإزالة كود ومراجع Google/Cloudflare/Vinext القديمة.
- إزالة خطوة البناء الخطرة `prisma db push --accept-data-loss`، وتفعيل فحص TypeScript، وإضافة GitHub Actions للفحص والبناء.

## بوابة القبول قبل الدمج
يلزم فحص آخر commit في GitHub Actions، ثم تشغيل التطبيق محليًا على قاعدة اختبار فارغة والتحقق من:
1. إعداد حساب المدير وتسجيل الدخول وتعطيل مستخدم.
2. شراء أكثر من بند لنفس المنتج والتحقق من الكمية ومتوسط التكلفة.
3. بيع نقدي وآجل، ونقص المخزون، وإعادة الطلب بنفس مفتاح منع التكرار.
4. مرتجع جزئي وكامل ومتكرر؛ وعدم السماح بإرجاع كمية زائدة.
5. تحصيل عميل وسداد مورد، ورفض الدفع الزائد وربط الدفع بفاتورة تخص طرفًا آخر.
6. جرد متعدّد الأصناف مع بند فاشل، والتأكد من التراجع عن العملية كلها.
7. إغلاق وردية مرتين والتحقق من النقد الفعلي والمرتجعات النقدية فقط.
8. إنشاء نسخة SQLite وفحص سلامتها واستعادتها إلى قاعدة منفصلة.

## بيانات المحل
لم يتم استيراد نسخة المحل أو ترحيل بيانات حقيقية حتى الآن. بعد نجاح الكود والاختبارات، سنحدد نوع النسخة الاحتياطية ثم نستعيدها إلى قاعدة تجريبية، ونقارن أعداد السجلات ومجاميع المبيعات والمخزون وأرصدة العملاء والموردين قبل اعتمادها.

**لا تدمج هذا الفرع ولا تشغله على نسخة المحل الحالية قبل نجاح الاختبارات والاستعادة التجريبية.** خذ نسخة مستقلة من البيانات قبل كل ترقية للمخطط.
