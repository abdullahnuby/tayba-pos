# طيبة POS — نظام إدارة محل محلي

طيبة POS برنامج لإدارة محل الملابس والمبيعات والمشتريات والمخزون والعملاء والموردين والورديات. اتجاه التشغيل المعتمد الآن هو **برنامج محلي مستقل**: قاعدة البيانات التشغيلية ملف SQLite على جهاز المحل، وليست Google Sheets أو قاعدة بيانات سحابية.

## وضع المشروع

الفرع `local-only-hardening` هو فرع الإصلاح والتحويل إلى التشغيل المحلي. **لا تستبدل به نسخة المحل الحالية ولا تدمجه في `main` قبل نجاح فحوصات البناء واختبارات قبول العمليات المحاسبية واستعادة نسخة البيانات الاحتياطية.** لم تُستعد بيانات المحل داخل هذا الفرع حتى الآن.

## ما الذي يخزنه محليًا؟

- ملف قاعدة البيانات الافتراضي: `data/tayba.db`.
- النسخ الاحتياطية الكاملة: مجلد `backups/` بجوار المشروع.
- الشاشة المسماة «النسخ الاحتياطي» تنشئ لقطة SQLite باستخدام `VACUUM INTO` وتحفظ نسخة محلية قابلة للتحميل، وتحتفظ بآخر 30 نسخة محلية.
- تصدير Excel مناسب للمراجعة والتحليل فقط؛ **لا يغني عن ملف SQLite الكامل عند الاستعادة**.
- لا توجد مزامنة أو أرشفة تشغيلية إلى Google Sheets. المسارات القديمة الخاصة بالمزامنة ترفض الطلبات بدل تنفيذ عمليات سحابية.

> مهم: لأن قاعدة البيانات تحتوي مبيعات وأرصدة ومعلومات دخول، لا ترفع `data/` أو `backups/` إلى GitHub ولا تضع ملف النسخة الاحتياطية داخل `public/`.

## المتطلبات

- Node.js 22 أو إصدار متوافق مع إصدار Next.js المستخدم.
- npm.
- مساحة قرص كافية لملف قاعدة البيانات والنسخ الاحتياطية.

## الإعداد لأول مرة

من مجلد المشروع:

```bash
npm install
```

انسخ `.env.example` إلى `.env`، ثم ضع قيمة سرية قوية وفريدة في `AUTH_SECRET`. لا تستخدم قيمة المثال في تشغيل حقيقي.

```bash
npm run db:setup
npm run dev
```

افتح `http://127.0.0.1:3000` واتبع شاشة إعداد الحساب الإداري الأول. الخادم مربوط بعنوان loopback حتى لا يصبح متاحًا تلقائيًا لأجهزة الشبكة. لإنشاء نسخة تشغيل محلية:

```bash
npm run build
npm run start
```

لا تنشر هذا الإصدار على Vercel أو Cloudflare؛ ملفات SQLite المحلية ليست قاعدة بيانات دائمة صالحة لتشغيل متعدد النسخ على خدمات الاستضافة عديمة الحالة.

## النسخ الاحتياطي والاستعادة

1. من شاشة «النسخ الاحتياطي»، اختر «إنشاء نسخة SQLite وتنزيلها».
2. تأكد من ظهور النسخة في قائمة النسخ المحلية، ثم انسخ ملف `.db` الذي تم تنزيله إلى وسيط منفصل وآمن.
3. قبل أي تحديث للبرنامج، أوقفه وخذ نسخة مستقلة من ملف قاعدة البيانات الحالي.
4. لا تستعد ملفًا أو تنقل قاعدة البيانات أثناء تشغيل البرنامج. الاستعادة تحتاج إيقاف التطبيق، والتحقق من نوع ملف النسخة، ثم ترقية مخطط قاعدة البيانات بعد الاستعادة إذا كان أقدم من إصدار البرنامج.

استعادة بيانات النظام القديم (سواء ملف SQLite أو Excel أو CSV) مهمة منفصلة عن بناء البرنامج؛ لا تستوردها على نسخة المحل الحية. بعد تثبيت نسخة مستقرة، تُجرى الاستعادة على نسخة تجريبية أولًا مع مقارنة عدد السجلات وإجماليات المخزون والمبيعات والأرصدة.

## أوامر مفيدة

| الأمر | الغرض |
|---|---|
| `npm run dev` | تشغيل التطوير محليًا |
| `npm run build` | توليد Prisma ثم بناء Next.js |
| `npm run start` | تشغيل النسخة المبنية |
| `npm run db:setup` | إنشاء/تحديث مخطط SQLite المحلي من Prisma |
| `npm run db:studio` | فتح Prisma Studio لفحص قاعدة البيانات |

**خذ نسخة احتياطية قبل تشغيل `npm run db:setup` على قاعدة بيانات بها بيانات فعلية.** لا يوجد أمر reset تلقائي؛ الأمر `npm run db:reset` مرفوض عمدًا لحماية بيانات المحل.
